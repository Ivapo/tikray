### Phase 10 exit gate — 2026-08-18 — **PASSED**, and how its own close-out was found incomplete

Items 1–4 run as 7 assertions in `tests/gate_phase10.rs`, item 5 is Phases 1–9's
gates byte-identical and green, and the human item was run in iTerm2. **104
assertions green**, linter green.

**The close-out was incomplete when the phase was implemented, and nothing in
Phase 10's own three review rounds found it.** Item 5 names a hidden directory
opening, `←` landing on the parent's first row, `a` doing nothing and the footer
wording — and `scripts/gate-phase4.sh` asked none of them. It surfaced only when
**Phase 11's** reviewer read the script from outside, looking for what it
over-covered and noticing what it under-covered. Worth recording as a property
of the loop rather than a slip: a phase's review reads the phase, and a human
item is checked for being *specific* rather than for being *runnable*. Nothing
compares an item's clauses against the script that is supposed to run them.

**Two bugs in the phase's own test, both caught after it first went green.** The
fixture tree was built at a shared path while cargo runs tests in parallel, so
one test's teardown raced another's setup — it passed a single-file run **by
luck** and failed the full suite. Phase 3's `workdir(name)` idiom exists for
exactly this and was not reached for. And the §8 fixture originally held one
entry, so `src/tui.rs:index_of`'s row-0 fallback answered the highlight question
whether or not the selection was wired; it now carries a visible `sub/` above the
hidden file, so landing on row 0 is a **wrong** answer rather than an accidental
right one.

**Three scripted-edit failures in one phase**, all recorded in the rounds entry
above and worth the summary here because they are one class: an assertion that
threw and was not retried; a whole-file `replace(…, 1)` that matched **Phase
7's** text instead of Phase 10's, silently altering shipped prose; and a
post-condition that searched for a string spanning a line break, producing a
false alarm about an edit that had applied perfectly. The defence adopted midway
— assert the post-condition, not the pre-condition — is right, and the third
failure shows the check needs writing as carefully as the edit.

### Round 2 — Phase 8 only — 2026-08-18 — clean-room reviewer (resumed) — **READY**

Zero blocking. Converged in two rounds. **This round is the corpus's best example
of a reviewer measuring rather than reasoning**, and it settled two questions
that argument alone would have left open.

**Gate item 4's equality was verified by compiling it.** The item asserts
`pane_view(…, 1)` matches the shipped pair, and the byte half is not obvious:
`pane_view` encodes `crop_imm(0,0,w,h)` where `pane_sequence` encodes the buffer
itself. Rather than reason about it, the reviewer compiled both against
`image 0.25.10` across four colour types — `rgb8 1200×800`, `rgba8 37×91`,
`rgb16 64×48`, `luma8 1×1` — and got `variant_same=true, png_identical=true` on
all four. A full-rect `crop_imm` round-trips through `dynamic_map!` preserving
variant and pixels, so §2.1's waist survives and the payloads are byte-identical.
It also confirmed `crop_imm` clamps an out-of-range rect internally, which makes
item 3's crop property a real assertion rather than one the type system gives.

**B3's fix was re-swept, not spot-checked:** 330,750 cases over seven panes
including degenerate ones, sources to 16,000 per axis, all three levels — zero
`L=1` mismatches against `fit`, zero zero-dimensions, zero spills, zero
over-crops. Including the 48–55 × 1003 family and round 1's 50×1023.

Four non-blocking, all folded in after convergence. **The best of them corrects
this phase's argument for the second time, and the correction is the finding.**
The phase first claimed the output clamp was load-bearing (wrong — that
measurement was of a formulation never adopted), then round 1 demoted it to
provably-unreachable, and round 2 showed *that* is wrong too: the floor-at-1
introduced by B2's fix creates the corner the proof excludes, and with a pane
axis under 4 pixels the clamp genuinely fires — 38 cases in a sweep. Unreachable
with real cell geometry, since a one-cell pane is 16×36 px, so nothing is broken
and the `min` stays. What is recorded instead is the lesson: **the arithmetic's
edges are found by sweeping, not by proving**, which this phase has now
demonstrated three times on itself.

The other three: `zoom_view`'s `None` domain was stated only for `L = 1`, while
gate item 3 sweeps a domain that needs one; item 4's equality was written as a
pseudo-equation whose two sides have different types, now two equalities; and
item 2 is **tautological by design** — decision 3 makes `zoom_view` *return*
`fit`'s pair, so the sweep tests that the special case still exists rather than
that two computations agree. That is the regression protection wanted, and it now
says so, so no reader mistakes it for an independent check.

Two answers worth keeping from the questions put to the round. The "which `None`"
seam is unambiguous because both sources collapse to Phase 4 decision 3's single
meaning, and the only diverging input — a zero-axis buffer — is unreachable:
`image`'s decoders reject zero dimensions, `usvg`'s `IntSize` is non-zero by
construction, and the encoder refuses one anyway. And `scale -> f64` is safe at
both call sites, with one thing worth knowing: `tests/gate.rs` pins the
*viewport* half of `fit`'s zero guard, so a delegating refactor that dropped it
goes red — but the *native* half is pinned by nothing, and is protected only by
being unreachable from `load`.

### Round 1 — Phase 1 only — 2026-08-16 — clean-room reviewer with repo access — **NOT READY**

**Round 0 (asked once for this episode, not re-litigated after).** *Does this
phase produce the observable, and is it the right one?* Yes — Phase 1 draws a
PNG or JPEG inline in iTerm2, which is literally the first half of the recorded
observable, so it produces one rather than having to argue it does not; and it
is the right first one because it is the shortest path from no code to anything
visible, and it retires the project's largest unknown (does the inline protocol
display what we emit, at a sane size, in this terminal) before SVG, conversion
or a TUI are stacked on it. Recorded caveat: **Phase 1 in isolation duplicates
`chafa`/`timg`** — this project's reason to exist lives in Phase 3, so a Phase 1
that shipped alone would be a nicer-packaged version of a tool the user already
has. That is an argument for keeping Phase 3 non-optional, not against building
Phase 1 first.

The repo had no code at this round, so there were zero `file:symbol` citations
to check and grounding rested entirely on external facts. Those were verified
against primary sources (iTerm2's Inline Images Protocol page, `docs.rs/image`).

Two blocking findings:

- **B1 — the display path as specified would have downloaded the file instead of
  showing it.** §2.3 described "print the escape sequence" while never
  enumerating a single `File=` argument, and `inline` **defaults to 0**: iTerm2's
  documentation says the file "will be downloaded with no visual representation
  in the terminal session." Implemented from the spec alone, that is a silent
  download, exit 0, nothing displayed — exactly the failure §1 names when it
  refuses to treat the escape sequence as the observable. The spec identified the
  hazard and then omitted the one argument preventing it. **Resolved** in §2.3 by
  making `inline=1` mandatory, pinning the full argument string, and asserting the
  byte in gate item 2.
- **B2 — the gate's "outside iTerm2 → exit non-zero" clause named no detection
  mechanism, and the candidates disagree.** Four inconsistent environment signals
  plus iTerm2's own Feature Reporting protocol, differing in behaviour (only
  `LC_TERMINAL` survives ssh; none survive plain tmux; WezTerm implements the
  protocol but is not iTerm2) and by an order of magnitude in cost — which also
  changed whether the phase was one plan-mode pass. **Resolved** by new §2.7:
  tty check plus `TERM_PROGRAM`/`LC_TERMINAL`, Feature Reporting recorded as
  rejected *with its trade-off written down* rather than silently omitted, and
  `--force` as the escape hatch for the known false negatives.

Nine non-blocking findings, all accepted: the gate had nothing machine-checkable
and its sizing clause was self-certifying (the implementer chose the default it
was checked against, so it could not fail); "fits the window" was satisfiable by
upscaling a 16×16 icon to fill the screen; OQ-3's option list contradicted the
gate meant to resolve it; §2.3 never mentioned the protocol's sizing arguments
exist; the supported-input allowlist was unstated while §2.4 assigned that duty
to a gate that did not discharge it; extension-vs-content detection was Phase 1's
choice with Phase 2 already constraining it; the buffer type was unnamed and
§2.1's "RGBA" contradicted §2.3's "no colour-approximation anywhere"; the phase
named no files, signatures or dependency versions, against conventions §3; the
JPEG→RGBA→PNG round-trip was presented as forced when it is chosen; OQ-5 named
no phase, against conventions §4; and §2.4 overstated WebP (encode is

**Notable adjudication — a suggestion resolved differently.** The reviewer
proposed delegating sizing to the terminal with `width=100%;height=100%`,

possible without stretching", which upscales, and a 16×16 favicon would fill the
window as a screenful of blurred squares. Round 2 agreed on re-review — the
suggestion would have reintroduced exactly the case gate item 5 now names.
